# doc/thesis/: rules for the thesis, its corrections and the remarks on it

- Never edit the thesis. It is a submitted document and can't be changed. Correct it in [`thesis-corrections.md`](thesis-corrections.md) instead.
- A correction is for something wrong in the thesis as written: an inconsistency, a typo, an omission, a false statement or a wrong step in a proof. Where the Rocq proof merely departs from the thesis's proof, record nothing: [`README.md`](README.md) says once that the two have diverged.
- Keep each correction as short as it can be. Say what is wrong and how to correct it, in general terms, and why the thesis's results still stand when that isn't obvious. Then list the places it applies, comma-separated, each by its definition, theorem or listing number and printed page, and end with a link to the PR or report that found it. Corrections with one cause share an entry; give the others an entry each.
- [`thesis-remarks.md`](thesis-remarks.md) holds notable observations about the thesis itself, made while formalising it, that are not errors in it. Add one only when a human has agreed to it, proposed in the PR; most discoveries don't qualify. Write it to last: it is about the thesis, never about the state of the formalisation, so nothing like "yet", "today" or "planned", and no reference to a file or lemma. Give the same references as a correction, the observation at a high level, a minimal example only where one helps, why it matters, and the PR or report that made it.
- Write maths in GitHub's LaTeX syntax: `$...$` inline and `$$...$$` for display.
- Don't use LaTeX spacing commands made of a backslash and punctuation, such as `\;`, `\,`, `\:`, `\!` or `\ `. Some Markdown viewers read them as escaped punctuation and show stray semicolons or commas. Use `\quad` or `\qquad` for space, and `\mathbin{.}` for a dot with space around it.
